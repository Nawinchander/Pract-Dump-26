Shortest Path with Dijkstra

Now let's make the backend problem significantly harder.

Problem

Build an API that receives a weighted graph and finds the shortest path between two nodes.

Example:

A --4-- B
|      / \
2     1   5
|    /     \
C --8------ D


Input:

{
  "graph": {
    "A": {
      "B": 4,
      "C": 2
    },
    "B": {
      "A": 4,
      "C": 1,
      "D": 5
    },
    "C": {
      "A": 2,
      "B": 1,
      "D": 8
    },
    "D": {
      "B": 5,
      "C": 8
    }
  },
  "source": "A",
  "target": "D"
}




Expected:

{
  "distance": 7,
  "path": ["A", "C", "B", "D"]
}

Because:

A → C = 2
C → B = 1
B → D = 5

Total = 8

Actually, with those weights the shortest path is 8, not 7:

A → C → B → D
2 + 1 + 5 = 8

This is exactly the kind of detail you should catch in an interview.



Why this is advanced

A naive implementation repeatedly scans all nodes:

O(V²)

A better implementation uses a Min Heap / Priority Queue:

O((V + E) log V)

This is much closer to what you'd discuss in a FAANG system/backend interview.

We will create a REST API:

POST /api/dsa/shortest-path

Understand the Min Heap

Dijkstra repeatedly needs:

"Give me the unprocessed node with the smallest distance."

For example:

A = 0
B = 4
C = 2
D = 8

We want:

C = 2

before:

B = 4
D = 8

A normal array would require scanning:

O(V)


A Min Heap gives us approximately:

Insert = O(log V)
Remove minimum = O(log V)

That's why the heap is important.


Understand the algorithm

Suppose:

A → B = 4
A → C = 2

C → B = 1
C → D = 8

B → D = 5

Start:

distance[A] = 0
distance[B] = ∞
distance[C] = ∞
distance[D] = ∞

Heap:

[0, A]



Process A

Neighbors:

B = 4
C = 2

Now:

A = 0
B = 4
C = 2
D = ∞

Heap:

[2,C]
[4,B]


Process C

C has:

C → B = 1
C → D = 8

For B:

2 + 1 = 3

Previously:

B = 4

New:

B = 3

For D:

2 + 8 = 10

So:

D = 10



Process B

B → D:

3 + 5 = 8

Previously:

D = 10

Therefore:

D = 8

Final:

A = 0
C = 2
B = 3
D = 8

Path:

A → C → B → D
