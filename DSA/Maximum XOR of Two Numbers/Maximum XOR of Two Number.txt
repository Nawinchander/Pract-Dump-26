Maximum XOR of Two Numbers
Difficulty: Hard
Topic

Binary Trie + Bit Manipulation + Greedy

Given:

nums = [3, 10, 5, 25, 2, 8]

Find the maximum:

nums[i] XOR nums[j]
Answer

Why Trie?

For XOR, each bit matters.

For every bit:

0 XOR 1 = 1
1 XOR 0 = 1

So we want the opposite bit whenever possible.

For example, if our current number has:

1

we prefer:

0

from the other number.

This becomes a greedy search from the most significant bit.



Dry Run

Input:

[3, 10, 5, 25, 2, 8]

For:

5 = 00101

We want another number with bits as opposite as possible:

11001

which is:

25

Therefore:

11100
11100₂ = 28

So:

findMaximumXOR([3, 10, 5, 25, 2, 8]);

returns:

28

Complexity

Let B be the number of bits.

Insert:    O(B)
Query:     O(B)
N numbers: O(N × B)

For 32-bit integers:

B = 31/32

Therefore effectively:

Time:  O(n)
Space: O(n)
