Integration test

An integration test should test multiple components together.

For example:

HTTP Request
     ↓
Controller
     ↓
Service
     ↓
Dijkstra
     ↓
Repository
     ↓
MySQL

That's different from your unit test.

The unit test asks:

Does Dijkstra calculate the correct answer?

The integration test asks:

Can the API execute the whole route-search workflow and save the result?




End-to-end testing

Your E2E test should look conceptually like:

Create user
     ↓
Create route
     ↓
Request shortest path
     ↓
Dijkstra executes
     ↓
Result stored in MySQL
     ↓
Traffic snapshot stored in MongoDB
     ↓
API returns result
     ↓
Verify database records

This is much closer to what a production backend actually does.
